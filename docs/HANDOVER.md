## 3. 直近の不具合と、その原因（重要）

### 配信したのに、追加したアイコンが出ない

**症状：** 再生ボタンを足して検証環境へ配信したが、**ボタンの場所だけ空いていて絵柄が出ない**。
強制リロード（Ctrl + Shift + R）でも直らない。検索の虫めがねなど**既存のアイコンは出る**。

**原因：`firebase.json` のキャッシュ指定。** アプリのコードではありません。

Flutter はアイコン用の `MaterialIcons-Regular.otf` を、**そのビルドで使っている
アイコンだけに削り込んで作り直します**（1.6MB → 13KB）。
つまり**名前は変わらないのに中身がビルドごとに変わる**ファイルです。

そこを `max-age=31536000, immutable`（1 年、取り直さない）にしていたため、

- `main.dart.js`（新しい）→ 再生ボタンを配置する
- `MaterialIcons-Regular.otf`（**古い**）→ 再生・一時停止・停止の絵柄を持たない

という組み合わせになりました。**場所だけ取って何も描かれない**という出方をします。

**直したこと：** `must-revalidate` に変更（`7917450`）。
`test/domain/hosting_cache_test.dart` で戻らないよう固定してあります。

**まだ残っている影響：** 一度でも開いたことがあるブラウザには、
古いフォントが「1 年取り直すな」の指定つきで残っています。**配信し直しても消せません。**
利用者に一度だけ **F12 → Application → Clear site data** をお願いする必要があります。
本番も同じ状態です（前回の本番配信は修正前の設定で行いました）。

**切り分け方：** シークレット ウィンドウで開いて直るなら、原因はキャッシュです。

**この件から学んだこと：**
「ファイル名が変わらない = 中身が変わらない」ではありません。
[AUDIT-CHECKLIST.md](AUDIT-CHECKLIST.md) の観点 6 に追記してあります。

### 本番でリスト作成の申請が `internal` で失敗する

**症状：** 本番環境でリスト作成を申請すると `internal` とだけ表示される。

**原因：Cloud Run の呼び出し許可が入っていません。** アプリのコードではありません。

`onCall` の関数は、Cloud Run の側で「誰でも呼べる」状態にしておく必要があります
（利用者の確認は関数の中で `request.auth` を見て行う設計です）。
Firebase CLI は関数を**新規作成したときだけ**この設定を入れます。

**2026-08-07 の初回本番配信は、20 件が「Failed to create」で失敗し、
再実行で「update」になって成功しました。** 関数はできたが、
**作成時にしか入らない呼び出し許可だけが入らなかった**状態です。
以後 `firebase deploy` を何度繰り返しても更新扱いなので直りません。

**直し方は [SETUP.md](SETUP.md) の「呼び出し可能関数が `internal` で失敗するとき」にあります。**
Cloud Shell から `gcloud functions add-invoker-policy-binding` を
**onCall の 15 件**に対して実行するのが早く、関数を止めずに済みます。
トリガーと定期実行は利用者が直接呼ばないので、対象外です。

**確かめ方：** Cloud Functions のログに次が出ていれば、この原因で確定です。

```
The request was not authenticated. ... Empty Authorization header value.
```

**出ていなければ別の原因です。** `internal` は関数の中で想定外の例外が出たときにも出ます。
ログの本文を読んでください。

`functions/test/setup_doc.test.ts` で、手順書の関数一覧が実装とずれないよう固定しました。
一覧から漏れた関数は、復旧手順を実行しても直らないためです。

### 再生ボタンを押しても鳴らない

**症状：** mp3 を登録して再生ボタンを押すと「再生できませんでした」。
検証環境・本番の両方で起きました。

**原因：`just_audio` の Web 版が組み込まれないままビルドされていた。**
アプリのコードの問題ではありません。

```
MissingPluginException(No implementation found for method init
on channel com.ryanheise.just_audio.methods)
```

Web 版が居ないため、Web には存在しないスマホ用の通信路を呼びに行き、
そこで止まっていました。`just_audio` は今回はじめて足した部品なので、
それ以前から残っている生成物が混ざると、**古い部品一覧がそのまま使われる**
ことがあります。`flutter clean` で直ります。

**この出方がいちばん危険です。**

- ビルドは成功する
- 配信も成功する
- 画面も普通に開く
- **その部品を使う操作だけ**が失敗する

どこにも赤が出ないまま機能だけが死にます。**自動テストでも捕まりません。**
テストは Dart のコードを直接動かすので、Web のビルドを通らないためです。

**手当て：** `scripts/deploy.mjs` が、部品の顔ぶれが前回のビルドから
変わっていたら自動で `flutter clean` します（`ec97064`）。
変わっていなければ何もしません（毎回消すとビルドが数分延びるため）。

### この 3 件に共通すること

**どれもアプリのコードの外側が原因でした。**

| 症状 | 原因のあった場所 |
| --- | --- |
| アイコンが出ない | 配信の設定（キャッシュ指定） |
| `internal` で失敗 | クラウド側の権限（Cloud Run の呼び出し許可） |
| 再生できない | ビルドの生成物（古い部品一覧） |

**手元で動くのに配信先で動かないときは、アプリの外側を疑う層に入れてください。**
`flutter test` はどれも緑のままでした。

### 原因を追えなくしていたのは、こちら側でした

「再生できませんでした」としか出ない作りにしていたため、
依頼者に何度も配信をやり直させました。例外を握りつぶしていたからです。

```dart
catch (_) { ...再生できませんでした... }   // ← 中身を捨てていた
```

**「失敗しました」とだけ出す作りは、直す機会そのものを奪います。**
いまは「詳細」から技術的な内容を読めます。同じ判断を他の画面でもしないこと。

### Windows 固有の注意

- 環境変数は `PATH` ではなく `Path`。大文字小文字を無視して既存のキーを探すこと
  （新しく `PATH` を作ると Windows からは別物になり、**PATH が消える**）
- `.cmd` は ASCII のみ。日本語を書くと文字化けして動かない
- `spawn(args[], {shell:true})` は引用符を付けずに連結する。Windows では 1 本の文字列で渡す
- `JAVA_TOOL_OPTIONS=` のような POSIX の書き方はコマンドプロンプトで動かない
- **`new URL(...).pathname` でファイルの場所を作らない。** Windows では
  `/C:/Users/...` と先頭にスラッシュが付いた形になり、`join` で繋ぐと
  `C:\C:\Users\...` になって開けない。`fileURLToPath` を使うこと
  （2026-08-07、監査で足したテストが Windows だけで落ちた）

**Windows 固有の不具合は、この環境では見つかりません。** ここは Linux
なので、書いた本人は緑を見て終わります。**Windows でしか動かない道
（`.cmd`・パス・環境変数）に触れたら、その旨を添えて依頼者に渡すこと。**
